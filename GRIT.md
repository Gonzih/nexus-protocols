# THE GRIT PROTOCOL - EXECUTION FRAMEWORK

**"I'm not going to stop until I get it done"**

Success comes from systematic persistence, not luck.

---

## STEP 1: RESEARCH FIRST

- **Use WebSearch** for current documentation
- **Use WebFetch** to get exact ABIs/addresses
- **Verify contract addresses** on BaseScan/Etherscan
- **Check pool existence** before attempting swaps
- **Never assume** - always verify with live data

---

## STEP 2: BABY STEPS EXECUTION

- **Test simplest component first** (single function call before complex flow)
- **Build complexity incrementally** (working foundation → add features)
- **Each failure = precise learning data** (document what broke and why)
- **Document every micro-breakthrough** (track progress explicitly)

---

## STEP 3: SYSTEMATIC DEBUGGING

- **Get exact error codes/revert reasons** (read the actual error message)
- **Use Web3 transaction replay** for diagnosis (simulate before sending)
- **Check allowances, nonces, gas estimates** (verify all prerequisites)
- **Verify contract addresses and ABIs** (wrong address = guaranteed failure)

---

## STEP 4: ROOT CAUSE ELIMINATION

- **Fix one issue at a time** (single variable changes)
- **Test fix in isolation** (confirm it works before adding complexity)
- **Proceed to next failure point** (systematic progression)
- **Never give up until completion** (GRIT = persistence through obstacles)
